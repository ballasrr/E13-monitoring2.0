# E13 Monitoring API — памятка для фронтенда

Бэкенд отдаёт только JSON и файлы, никаких шаблонов и страниц.
Интерактивная документация со всеми схемами — **http://127.0.0.1:8000/docs**,
машинное описание — **/openapi.json** (из него генерируются типы, см. ниже).

Базовый адрес всех ручек: `/api/v1`.

---

## Аутентификация

Пользователь один — администратор. Схема простая: логин отдаёт токен,
токен кладётся в заголовок каждого следующего запроса.

**Вход.** Тело — `application/x-www-form-urlencoded` (это стандарт
OAuth2 password flow, ради совместимости со Swagger), а не JSON:

```
POST /api/v1/auth/login
Content-Type: application/x-www-form-urlencoded

username=admin&password=asko2026
```

Ответ:

```json
{
  "access_token": "eyJ1aWQiOi...",
  "token_type": "bearer",
  "login": "admin",
  "full_name": "Администратор",
  "role": "admin"
}
```

**Все остальные запросы** несут заголовок:

```
Authorization: Bearer <access_token>
```

Без него — `401`. Токен подписан и живёт 30 дней.

**Выход:** `POST /api/v1/auth/logout` с тем же заголовком. Важно: сервер
не просто «забывает» токен, а увеличивает счётчик версии у пользователя,
после чего все ранее выданные токены перестают действовать — в том числе
выданные на других устройствах. Это осознанное решение: токен без
серверной отметки отозвать нельзя, а «выход», который не выходит, —
дыра в безопасности.

Хранить токен лучше в памяти приложения, а не в `localStorage`:
из `localStorage` его сможет прочитать любой выполнившийся на странице
посторонний скрипт.

## Формат ошибок

Все ошибки приходят одной формы, так что обработчик нужен один:

```json
{ "error": "Площадка не найдена" }
```

| Код | Когда |
|-----|-------|
| `401` | нет токена, токен протух или отозван после выхода |
| `403` | роли не хватает |
| `404` | объекта нет |
| `409` | конфликт — например, код площадки уже занят |
| `413` | файл больше допустимого размера |
| `422` | не прошла валидация полей |
| `429` | слишком много попыток входа подряд |
| `500` | ошибка сервера, подробности только в логах |

Текст в `error` написан по-русски и пригоден для показа пользователю.

## Ручки

### Площадки

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/stations` | Список. Параметры: `include_archived`, `limit`, `offset`. Общее число записей — в заголовке `X-Total-Count` |
| `POST` | `/stations` | Создать |
| `GET` | `/stations/{id}` | Карточка |
| `PATCH` | `/stations/{id}` | Изменить (только переданные поля) |
| `DELETE` | `/stations/{id}` | В архив — объект остаётся в базе |

### Оборудование

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/stations/{id}/chargers` | Зарядные станции площадки |
| `POST` | `/stations/{id}/chargers` | Добавить |
| `GET` `PATCH` `DELETE` | `/chargers/{id}` | Карточка, правка, удаление |
| `POST` | `/chargers/{id}/service` | Отметить проведённое ТО сегодняшним числом |

### Документы

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/doc-types` | Справочник типов документов |
| `GET` | `/stations/{id}/documents` | Актуальные редакции по площадке |
| `POST` | `/stations/{id}/documents` | Загрузка файла, `multipart/form-data` |
| `GET` | `/documents/{id}` | Карточка |
| `GET` | `/documents/{id}/versions` | Все редакции одного документа |
| `GET` | `/documents/{id}/content` | Скачать сам файл |
| `PATCH` | `/documents/{id}` | Правка карточки |
| `POST` | `/documents/{id}/make-current` | Сделать эту редакцию актуальной |
| `DELETE` | `/documents/{id}` | Удалить редакцию вместе с файлом |

**Про версии.** Повторная загрузка документа того же типа не затирает
старый, а создаёт новую редакцию: прежняя остаётся в истории с
`is_current: false`. На экране по умолчанию показывайте только текущие.

### Контроль сроков

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/compliance/config` | Правила и пороги — **источник правды** |
| `GET` | `/compliance/alerts` | Все замечания по сети, отсортированы по срочности |
| `GET` | `/compliance/stations/{id}` | Замечания и чек-лист по одной площадке |

Не дублируйте правила на фронте — берите их из `/compliance/config`.
Иначе при изменении требований придётся править в двух местах, и однажды
поправят только в одном.

Уровни замечаний: `overdue` (просрочено или нет обязательного документа),
`warning` (меньше 30 дней), `soon` (меньше 90 дней). Поле `days` —
сколько осталось; отрицательное значит просрочку.

### Выгрузка

| Метод | Путь | Что отдаёт |
|---|---|---|
| `GET` | `/export/registry.xlsx` | Книга Excel: площадки, оборудование, комплектность |
| `GET` | `/export/stations.csv` | Реестр площадок |
| `GET` | `/export/chargers.csv` | Оборудование |
| `GET` | `/export/compliance.csv` | Матрица комплектности |
| `GET` | `/export/stations.json` | Полный дамп |

Имя файла лежит в заголовке `Content-Disposition`, и он специально
открыт для чтения из JavaScript — по умолчанию браузер такие заголовки
скриптам не показывает. Так же открыт `X-Total-Count`: по нему строится
постраничная навигация в списке площадок.

## CORS

API отвечает только тем адресам, которые перечислены в переменной
`CORS_ORIGINS`. По умолчанию это `http://localhost:5173` — порт Vite.
Если фронтенд поднимается на другом порту, скажите — добавим, иначе
браузер молча отбросит ответ, и в консоли будет ошибка CORS.

Звёздочка `*` в продакшене запрещена кодом: с ней любой сайт сможет
дёргать API в браузере залогиненного человека.

## С чего начать

1. Поднять бэкенд: `docker compose up -d` в корне проекта.
2. Открыть `http://127.0.0.1:8000/docs` и пощёлкать ручки живьём
   через кнопку **Authorize** — так быстрее всего понять формат данных.
3. Сгенерировать типы из `/openapi.json`, а не писать их руками:

```bash
npx openapi-typescript http://127.0.0.1:8000/openapi.json -o src/api/types.ts
```

Тогда при изменении контракта на бэке TypeScript сам покажет, где
сломалось. Вручную переписанные типы расходятся с реальностью на
второй неделе.
